# Execution (Layer 3)

Deterministic Python tools called from orchestration after reading a directive in `directives/`.

See [docs/AGENTS.md](../docs/AGENTS.md). Prefer extending existing scripts before adding new ones.

For copy-and-paste workflow commands, see the [demo automation guide](../AUTOMATION_GUIDE.md), including pre/post uploads, reviews, endorsement, panelist and peer scores, post-defense archiving, adviser grades and minutes drafts.

## Available Tools

- `audit_library_filters.py`: Read-only public-library subject, technology and language coverage. Run with the backend virtual environment, optionally `--academic-year 2024-2025`, `--scope pit` and `--output .tmp/library-filter-audit.json`. Counts published projects once, reports Not specified fields, and keeps the entire database transaction READ ONLY. This is a coverage report, not a real-paper accuracy benchmark.

- `start_local_web.py`: Launches Django + Flutter Web on a shared LAN/phone hotspot IP. Use `--check` for adapter/API/CORS diagnostics or `--interface "Wi-Fi"` to select an adapter. See [the network guide](../docs/WIFI_IP_CONFIG_GUIDE.md).
- `audit_academic_calendar.py`: Read-only audit of missing semester calendars and out-of-range defense dates. An exact demo correction can be previewed with `--semester-id`, `--starts-on`, `--ends-on`, `--from-date`, `--to-date`, and `--expect-count`. Applying additionally requires `--apply`, an administrator `--actor-id`, a new `--backup` JSON path, and the existing `DEFENSYS_ALLOW_DEV_DB=1` opt-in for development data. It refuses count mismatches, recorded panel evaluations, published grades, and minutes; preserves assignments; and logs each correction.
  Its separate demo-baseline mode uses `--rebase-to-semester-id`, `--year-label`, `--expect-teams`, `--expect-enrollments`, and `--expect-capstone-teams`. It moves all current PIT/Capstone semester references to an empty second semester, changes fourth-year Capstone enrollment/sections to third year, corrects open participation snapshots and records the new intake. It preserves calendar dates and recorded PIT scores/files. Apply also requires the exact `--preview-revision` and a new recovery file inside `.tmp`; existing Capstone assessments, cohort records, closed participation, rollover history and populated destinations are refused. This is an explicit demo-data correction, not the normal semester activation or enrollment rollover workflow.
- `auto_peer_eval.py`: Simulate student peer evaluations through the REST API. From `execution/`, preview one cohort with `python auto_peer_eval.py --all-students --year 1 --dry-run`; remove `--dry-run` to submit. `--year` accepts 1–4 or labels such as `"1st Year"`, filters student discovery before `--limit`, and rechecks the dashboard team's `yearLevel` before scoring. It combines with `--team-id`, `--students`, `--stage`, `--session-id`, and `--semester-id`. Without `--year`, all cohorts remain eligible. Existing submissions and backend availability rules remain in force.
- `auto_panelist_eval.py`: Automated testing tool to simulate panelist evaluations for scheduled defenses via REST API.
- `auto_adviser_eval.py`: Automated testing tool to simulate capstone adviser grading for advised teams via REST API.

- `auto_review_endorse.py`: Simulate faculty review through each team's assigned account. From `execution/`, use `python auto_review_endorse.py --all-teams --year 1 --dry-run` for pre-file review/endorsement; add `--timing post` for post-file acceptance/archiving, optionally `--deliverable D3`. Remove `--dry-run` to save. PIT uses assigned section instructors; Capstone uses assigned advisers with `--scope capstone --stage "Concept Proposal"`. Existing endorsements/accepted files are preserved and missing/rejected files remain blocked. See [the review and endorsement guide](REVIEW_ENDORSE.md).
- `auto_documenter_minutes.py`: Simulate draft panelist comments through the assigned documenter. Add `--sign-all --admin USERNAME` to submit/sign through the documenter, assigned adviser and administrator APIs with their existing signatures. Supports `--stage`, `--semester-id`, `--session-id`; defaults to the active term/current project. Dry runs do not initialize drafts. Signed steps resume, completed records and existing comments are preserved, and writes are never retried. See the [demo automation guide](../AUTOMATION_GUIDE.md).
- `upload_deliverables.py`: Upload each team's own files as its student leader, like the evaluation tools. From `execution/`, use `python upload_deliverables.py --all-teams --year 1 --files "../sample_file/PIT1" --dry-run`; remove `--dry-run` to upload. All pre-deliverables are selected by default; deliverable folders choose the requirements and filenames identify teams. Add `--deliverable D1` for one requirement or `--timing post` for post-defense files. A unique PIT event is selected automatically; otherwise specify `--stage`. Existing uploads are preserved. Advanced saved plans remain available. See [the upload guide](UPLOAD_DELIVERABLES.md).

Panel, peer, adviser and minutes automation uses short-lived access tokens for active accounts in the appropriate role. Direct token generation does not create refresh-token records or change passwords. Peer evaluation's optional `--http-login` still uses the normal login endpoint.

### Panel evaluation automation

Configured concept hearings submit separate scores for every concept and each rubric target. Legacy concept hearings retain their ordinary rubric scoring. Both leave concept selection and the official outcome to the chair. Other Capstone verdicts default to `--verdict auto`, using the chair's refreshed API readiness and allowed outcomes; adviser/peer scores cannot override the panel cutoff. A missing chair never falls back to an administrator.

`auto_panelist_eval.py --all-panelists` includes faculty/admin panelists and assigned external invitations. `--panelists <usernames>` selects only those institutional accounts; `--external-only` selects only external invitations, and `--exclude-external` explicitly omits them. Existing evaluations are skipped. Drafts are preserved by default; `--include-drafts` retains their scores/remarks and fills missing scores before submission.

From `execution/`, start with `python auto_panelist_eval.py --all-panelists --scope pit --year 1 --dry-run`. Remove `--dry-run` to save simulated evaluations. `--stage` accepts a Capstone stage label or PIT event name. Discovery and API submissions share a schedule allowlist; without an explicit team, session, or semester, only the active semester is eligible. Each live submission refreshes its assignment and grading context. See [the panel evaluation guide](PANELIST_EVALUATION.md).

External access uses normal scoped guest JWTs and guest API endpoints. Expired, revoked, or unapproved invitations are reported with a reason; the script does not renew access. Dry runs use GET requests only and do not create refresh-token records. Scores use a 0–10 range scaled to each criterion's maximum, including zero and fractional maxima. Exit codes: `0` completed, `1` failed request/configuration, `2` unavailable evaluations or pending verdicts. PIT events never receive Capstone verdicts.
